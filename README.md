# Reminder

اپ اندروید Flutter برای نمایش «برنامه هفتگی مطالعه و فعالیت محمد»، تیک‌زدن فعالیت‌ها، نمایش فعالیت بعدی و یادآوری محلی سر ساعت. کاملاً آفلاین؛ بدون حساب کاربری، سرور، Firebase یا سرویس پولی.

- شناسه اندروید: `com.mohammad.reminder`
- Flutter ثابت: **3.32.8** (Dart 3.8.1)، همان نسخه در `pubspec.yaml` و CI
- Java 17، Android Gradle Plugin 8.7.3، Kotlin 2.1.0، Gradle 8.12، `compileSdk`/`targetSdk` 35، `minSdk` 23

---

## ۱. معماری

```
lib/
  models/            مدل‌ها: Activity، Completion، AppSettings، enumها
  data/              برنامه پیش‌فرض (۱۰۸ سطر)، parser سطرها، SQLite، shared_preferences، مخزن حافظه‌ای برای آزمون
  services/
    week_service.dart          محاسبه هفته A/B بر اساس تاریخ تقویمی
    schedule_service.dart      نمونه‌های روزانه، فعلی/بعدی/عقب‌افتاده، تداخل
    reminder_planner.dart      برنامه‌ریزی خالص یادآورها (پنجره ۱۴ روزه، شناسه پایدار)
    reminder_engine.dart       تیک، لغو، تعویق، همگام‌سازی اعلان‌ها (مشترک UI و پس‌زمینه)
    local_notifications_gateway.dart   اتصال واقعی به flutter_local_notifications
    backup_service.dart        پشتیبان/بازیابی JSON با اعتبارسنجی
    clock.dart                 ساعت قابل تزریق (برای آزمون)
  state/app_controller.dart    مدیریت وضعیت (Riverpod + ChangeNotifier)
  ui/                          صفحات: امروز، هفته، ویرایش، تنظیمات، شروع اولیه، مرور روزها
  background.dart              ورودی‌های پس‌زمینه (دکمه‌های اعلان، بازبینی یادآورها)
android/app/src/main/kotlin/com/mohammad/reminder/
  ResyncReceiver.kt            راه‌اندازی مجدد، به‌روزرسانی اپ، تغییر ساعت/منطقه زمانی، تغییر مجوز هشدار دقیق، تمدید روزانه
  HeadlessResync.kt            اجرای منطق Dart بدون رابط کاربری
  DailyResyncScheduler.kt      هشدار غیردقیق روزانه برای تمدید پنجره ۱۴ روزه
```

### یادآورها چطور کار می‌کنند

1. هر نمونه «فعالیت + تاریخ» یک شناسه اعلان پایدار دارد: `notifKey × 1000 + (روزِ تقویمی mod 1000)`. زمان‌بندی دوباره با همان شناسه، اعلان قبلی را جایگزین می‌کند، پس اعلان تکراری ساخته نمی‌شود.
2. اعلان‌ها با `zonedSchedule` در **AlarmManager خود اندروید** ثبت می‌شوند؛ به اجرای دائمی Dart، تایمر صفحه، اینترنت یا GitHub Actions وابسته نیستند.
3. اگر «هشدار دقیق» مجاز باشد `exactAllowWhileIdle`، وگرنه `inexactAllowWhileIdle` استفاده می‌شود و رابط اپ این محدودیت را نشان می‌دهد. WorkManager استفاده نشده است.
4. **پنجره ۱۴ روزه** هنگام باز شدن/برگشتن به اپ، پس از هر تیک یا ویرایش، و در این رویدادها تمدید می‌شود:
   - هشدار غیردقیق روزانه (حدود ۰۳:۱۵) که `ResyncReceiver` را اجرا می‌کند. یعنی اگر اپ هفته‌ها باز نشود، یادآورها ادامه پیدا می‌کنند.
   - `BOOT_COMPLETED`، `MY_PACKAGE_REPLACED`، `TIME_SET`، `TIMEZONE_CHANGED` و تغییر مجوز هشدار دقیق.
5. دکمه‌های اعلان «انجام شد» و «تعویق ۱۰ دقیقه» (مدت از تنظیمات) در isolate پس‌زمینه اجرا می‌شوند و بدون باز شدن اپ ذخیره می‌کنند. «انجام شد» منطق فعالیت بعدی را هم اجرا می‌کند و اعلان کوتاه «فعالیت بعدی» می‌دهد.
6. تعویق فقط یک اعلان جدا (شناسه منفی پایدار) می‌سازد و ساعت هیچ فعالیتی را تغییر نمی‌دهد.
7. نمونه‌هایی که زمان یادآورشان گذشته، دوباره زمان‌بندی نمی‌شوند؛ پس بازکردن اپ یا برداشتن تیک باعث اعلان‌های پشت‌سرهم نمی‌شود.

### هفته A/B

هفته از شنبه شروع می‌شود. تعداد هفته بین «شنبه مبنا» و شنبه هفته موردنظر از **شماره روز تقویمی** حساب می‌شود (نه اختلاف میلی‌ثانیه)، پس DST یا تغییر منطقه زمانی نتیجه را خراب نمی‌کند. زوج = نوع مبنا، فرد = نوع دیگر.

### زمان‌های نامعلوم

- شروع مدرسه دوشنبه، سه‌شنبه و چهارشنبه در برنامه اصلی مشخص نیست؛ ساعت ساختگی (مثلاً 07:00) گذاشته **نشده**. از تنظیمات برای هفته A و B جدا قابل تعیین است.
- متن «مدرسه تا 13:00 یا 15:00، مطابق هفته» عیناً حفظ شده و تا وقتی ساعت پایان سه‌شنبه/چهارشنبه را تعیین نکنی، همین متن نمایش داده می‌شود.
- فعالیت بدون ساعت شروع در چک‌لیست می‌ماند، برچسب «نیازمند تنظیم ساعت شروع» می‌گیرد و یادآور شروع ندارد.
- اگر مدرسه تا 15:00 باشد، با فعالیت 14:00 «تداخل زمانی» نشان داده می‌شود؛ هیچ چیز خودکار جابه‌جا یا حذف نمی‌شود.
- «بیدار شدن» رویداد لحظه‌ای است (پایان ندارد). «23:00–23:30 خواب» دقیقاً همین بازه است.

### ذخیره‌سازی

- SQLite (`sqflite`): جدول `activities` و جدول `completions` با کلید یکتای `(activity_id, date)`.
- برنامه پیش‌فرض فقط در `onCreate` دیتابیس (نصب اول) یا با «بازگردانی برنامه پیش‌فرض» وارد می‌شود. مهاجرت‌ها در `AppDatabase._migrations`.
- تنظیمات سبک در `shared_preferences`.
- پشتیبان JSON شامل فعالیت‌ها، تنظیمات و تاریخچه است؛ قبل از بازیابی کل ساختار اعتبارسنجی می‌شود و بازیابی فقط با تأیید انجام می‌شود.

## ۲. اجرای محلی

پیش‌نیاز: Flutter 3.32.8، Android SDK، Java 17.

```bash
# نصب نسخه ثابت Flutter (مثلاً با fvm یا از آرشیو رسمی)
flutter --version        # باید 3.32.8 باشد

# فقط بار اول: ساخت gradlew و gradle-wrapper.jar (فایل‌های موجود بازنویسی نمی‌شوند)
flutter create --platforms=android --org com.mohammad --project-name reminder .

flutter pub get
dart format lib test
flutter analyze
flutter test
flutter run                     # روی گوشی وصل‌شده یا شبیه‌ساز
flutter build apk --debug
```

خروجی debug: `build/app/outputs/flutter-apk/app-debug.apk`

**pubspec.lock:** بعد از اولین `flutter pub get` فایل `pubspec.lock` را commit کن تا نسخه‌ها ثابت بمانند. CI اگر این فایل باشد با `--enforce-lockfile` اجرا می‌شود، و اگر نباشد آن را می‌سازد و به‌صورت artifact به نام `pubspec-lock` می‌گذارد تا دانلود و commit کنی.

## ۴. اجرای Actions و دانلود APK

1. در مخزن GitHub به تب **Actions** برو.
2. workflow **Android APK** با هر push اجرا می‌شود؛ برای اجرای دستی **Run workflow** را بزن.
3. مراحل: checkout، نصب Java 17 و Flutter 3.32.8، `pub get`، بررسی قالب‌بندی، `flutter analyze`، `flutter test`، بیلد APK، آپلود.
4. اگر آزمون یا بیلد شکست بخورد، اجرا قرمز می‌شود و APK ساخته نمی‌شود. (بررسی قالب‌بندی عمداً فقط هشدار می‌دهد و بیلد را متوقف نمی‌کند.)
5. بعد از اجرای سبز، پایین صفحه اجرا در بخش **Artifacts**:
   - `reminder-debug-apk` ← `app-debug.apk` (امضای debug، همیشه ساخته می‌شود)
   - `reminder-release-apk` ← `app-release.apk` (فقط اگر Secrets تنظیم شده باشد)
   - `pubspec-lock` ← برای commit کردن
6. مسیرها داخل CI:
   - debug: `build/app/outputs/flutter-apk/app-debug.apk`
   - release: `build/app/outputs/flutter-apk/app-release.apk`

اگر Secrets نباشد، مرحله release رد می‌شود و پیام «Release APK skipped» می‌بینی. APK debug نسخه release **نیست**.

`versionCode` برابر شماره اجرای workflow (`github.run_number`) است و با هر اجرا بیشتر می‌شود.

### ثابت کردن Actions با SHA

workflow فعلاً از تگ‌های اصلی پشتیبانی‌شده استفاده می‌کند (`actions/checkout@v4`، `actions/setup-java@v4`، `subosito/flutter-action@v2`، `actions/upload-artifact@v4`). برای امنیت بیشتر، هرکدام را با SHA کامل همان نسخه عوض کن، مثلاً:

```yaml
uses: actions/checkout@<40-char-sha>   # v4.x.y
```

SHA را از صفحه Releases هر Action در GitHub بردار.

## ۵. ساخت keystore و تنظیم Secrets

یک بار روی کامپیوتر خودت:

```bash
keytool -genkeypair -v \
  -keystore reminder-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias reminder
```

رمزها را جای امن نگه دار. **اگر این فایل یا رمزش گم شود، دیگر نمی‌توانی نسخه بعدی را روی نسخه نصب‌شده به‌روزرسانی کنی.**

تبدیل به base64:

```bash
base64 -w 0 reminder-release.jks > keystore.b64    # Linux
base64 -i reminder-release.jks | tr -d '\n' > keystore.b64   # macOS
```

در GitHub: **Settings ← Secrets and variables ← Actions ← New repository secret**:

| نام Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | `reminder` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

CI فایل keystore را در پوشه موقت runner بازسازی می‌کند، `android/key.properties` را می‌سازد و در پایان هر دو را پاک می‌کند. رمزها در لاگ چاپ نمی‌شوند.

بیلد release محلی: فایل `android/key.properties` بساز (commit نکن):

```properties
storeFile=/absolute/path/reminder-release.jks
storePassword=...
keyAlias=reminder
keyPassword=...
```

بعد `flutter build apk --release`. بدون این فایل، بیلد release عمداً خطا می‌دهد تا تصادفاً با کلید debug امضا نشود.

### نکته مهم debug ← release

APK debug با کلید debug همان runner امضا می‌شود و این کلید در هر اجرای CI ممکن است فرق کند. اندروید به‌روزرسانی با کلید متفاوت را قبول نمی‌کند. برای رفتن از نسخه آزمایشی به release:

1. در اپ: تنظیمات ← «ذخیره فایل پشتیبان».
2. نسخه debug را حذف کن.
3. APK release را نصب کن.
4. تنظیمات ← «بازیابی از فایل».

از آن به بعد همیشه APK release با **همان کلید** نصب کن؛ داده‌ها حفظ می‌شوند. `applicationId` هرگز نباید تغییر کند.

## ۶. نصب APK روی گوشی

1. فایل zip artifact را دانلود و باز کن.
2. APK را به گوشی منتقل کن.
3. هنگام نصب، اجازه «نصب از منابع ناشناس» را برای برنامه مدیریت فایل بده.
4. اپ را باز کن، شنبه مبنا و نوع A/B را انتخاب کن.
5. اجازه اعلان را بده و در صفحه «هشدارها و یادآوری‌ها» Reminder را فعال کن.
6. پیشنهاد: تنظیمات اندروید ← برنامه‌ها ← Reminder ← باتری ← «بدون محدودیت».

## ۷. محدودیت‌های واقعی یادآوری در اندروید

- **بستن معمولی** (کشیدن از لیست اخیر) یادآورها را متوقف نمی‌کند.
- **Force stop** همه هشدارهای اپ را پاک می‌کند؛ تا دوباره اپ را باز نکنی، هیچ یادآوری (و تمدید روزانه) اجرا نمی‌شود. این رفتار خود اندروید است.
- بعضی سازندگان (Xiaomi/MIUI، Huawei، Samsung، Oppo، Vivo و…) محدودیت باتری شدید دارند و ممکن است هشدارها را دیر بدهند یا حذف کنند.
- اگر اجازه اعلان رد شود، یادآور نمایش داده نمی‌شود. اگر هشدار دقیق مجاز نباشد، یادآور تقریبی است و ممکن است دیرتر برسد.
- برای اندروید ۱۴ به بعد، «هشدار دقیق» برای نصب‌های جدید به‌صورت پیش‌فرض خاموش است و باید دستی فعال شود. مجوز محدودشده `USE_EXACT_ALARM` عمداً استفاده نشده است.
- پنجره ۱۴ روزه هر روز با یک هشدار غیردقیق تمدید می‌شود؛ اگر گوشی مدت طولانی این هشدار را اجرا نکند (مثلاً بعد از Force stop)، بعد از ۱۴ روز یادآوری نمی‌رسد تا اپ باز شود.
- در حالت «زمان گوشی»، پس از تغییر منطقه زمانی یادآورها به‌صورت خودکار بازبینی می‌شوند. در حالت `Asia/Tehran` زمان‌ها همیشه به وقت تهران است.

## ۹. چک‌لیست تست روی گوشی واقعی

- [ ] اجازه اعلان: پذیرفتن ← کارت وضعیت سبز / رد کردن ← پیام قرمز و دکمه «اجازه دادن»
- [ ] هشدار دقیق: فعال‌سازی ← «یادآوری دقیق فعال است» / رد ← پیام «تقریبی»
- [ ] یک فعالیت آزمایشی ۲ دقیقه بعد بساز؛ اپ در پس‌زمینه ← اعلان برسد
- [ ] اپ را از لیست اخیر ببند ← اعلان بعدی برسد
- [ ] Force stop ← اعلان نمی‌رسد؛ اپ را باز کن ← یادآورها دوباره تنظیم شوند
- [ ] گوشی را ری‌استارت کن (بدون باز کردن اپ) ← یادآور بعدی برسد
- [ ] روی اعلان «انجام شد» بزن ← بدون باز شدن اپ تیک بخورد و «فعالیت بعدی» بیاید
- [ ] «تعویق» ← بعد از ۵/۱۰/۱۵ دقیقه (طبق تنظیمات) دوباره بیاید؛ ساعت فعالیت عوض نشود
- [ ] تغییر هفته: ساعت گوشی را به شنبه بعد ببر ← A/B و دوشنبه عوض شود
- [ ] تغییر روز: نیمه‌شب ← چک‌لیست روز جدید خالی، تیک‌های دیروز در «مرور روزها» باقی
- [ ] تغییر منطقه زمانی گوشی ← یادآورها بازبینی شوند؛ با گزینه Asia/Tehran وقت تهران حفظ شود
- [ ] نصب APK release، تیک چند مورد، نصب release جدیدتر روی آن ← داده‌ها باقی بمانند
